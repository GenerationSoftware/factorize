---
title: Integration access
description: Connect external services used by Trigger inputs and MCP clients.
---

Integrations hold server-side credentials used to validate provider webhooks or
make authorized API requests. Select only the integrations needed for your
Triggers or MCP connection. Credentials are encrypted and never returned by
Factorize APIs.

Bearer API, GitHub, Linear, ClickUp, X, Fly.io, exe.dev, Amp, and Cloudflare REST API
integrations have distinct setup flows. Cloudflare Tail is retired. Use the browser's Integrations page to connect or revoke
credentials and to choose which MCP clients may access them.

Choose **Delete** on a supported integration to preview its impact, then confirm.
Deleting removes the connection from Factorize, not the provider. For Linear,
Factorize removes its saved OAuth connection and webhook routing for that
workspace. Affected Trigger sources, Event lookups, and client or workload
access are listed before confirmation. A Trigger with no sources left is
removed, but Event definitions, subscriptions, and recorded occurrences are
kept. Reconnecting does not restore removed configuration or grants.


### Hetzner Cloud

Open **Integrations → Hetzner Cloud** and enter a project token with **Read**
permission for inventory. To let clients provision servers, explicitly enable
provisioning and use a token with **Read & Write** permission in the same
project. Factorize validates inventory on save; Hetzner checks write permission
when a server is created. Replacing or deleting the project clears the previous
client permissions and Factorize's stored SSH keys and enrollments. Reassign
access for the intended clients after replacing the connection.

The owner can enable **Hetzner Cloud** in a client's permissions. The change
takes effect on the current OAuth connection. Without that checkbox the client
cannot list servers, create servers, access its Hetzner key, or check SSH.
With access the client can call `list_hetzner_servers` and
`get_hetzner_ssh_public_key`. Each OAuth installation gets a different
Factorize-managed key. The private key is encrypted and is never returned.

#### Provision a server

When provisioning is enabled, `create_hetzner_server` accepts an intentional
lowercase name, a small server type, a supported location, and a request UUID.
It provisions one Ubuntu 24.04 server with public IPv4. The project's cloud
resources may incur charges. Check size availability and pricing in Hetzner
first. Factorize reserves up to three create attempts per day and 20 per
connection, including uncertain attempts.

Reuse the same request UUID if the first result is uncertain. Factorize looks
up the original creation and won't send a second create request for that UUID.
Check the provider console before starting a different request. Factorize
does not automatically delete servers in cleanup; owners can do that in
Hetzner.

The server starts with the requesting client's restricted public key assigned
to the dedicated non-root `factorize-agent` account through cloud-init. Server
creation does not prove that bootstrap finished. In **View servers**, an owner
must independently obtain the server's Ed25519 host-key fingerprint from a trusted
console and enroll `factorize-agent` for SSH authentication. Leave client
selection automatic for provisioned servers.

#### Enroll an existing server

Choose an authorized client, a dedicated non-root account, and an Ed25519
host-key fingerprint from the trusted server console. Install the complete
restricted public-key line shown by Factorize on that account. Leaving the
client blank on an existing server makes it owner-only. For older shared
enrollments, delete and re-enroll with the intended client and replace the old
key on the server before checking again.

`check_hetzner_ssh` checks only servers enrolled for the calling client. It
revalidates the project's server and enrolled IPv4, authenticates with the
pinned host key, and closes immediately. It cannot run `ls` or any other
command. The server needs a reachable public IPv4 address and SSH on port 22.
Remove the authorized key from the server when retiring access; removing the
integration or enrollment in Factorize does not change the server.
