---
title: Connect your accounts
description: Browser setup, resource access, and delivery verification.
---

Sign up with email/password, verify email, then open [Settings → Integrations](https://app.factorize.sh/settings). Linear OAuth connects a workspace; it does not sign you in to Factorize.

| Account | Browser action and required access | Verification |
| --- | --- | --- |
| exe.dev | Add an account-level token, test credentials, choose Codex/Claude/Pi and VM tags, save. Needs VM listing/creation/SSH/deletion and tagged repository/model integrations. | Test connection, then `list_execution_targets`; optionally diagnose the saved connection. |
| Amp | Add access token and project; ensure project/model/repository access. | Test and save, then discover the `amp:` target. |
| Linear | Connect Linear and approve the workspace. Your account must access the selected project and issues; organization policies may require an administrator. | Select project/rules in the browser editor, send one matching event, inspect delivery/run. |
| ClickUp | Connect ClickUp and approve the intended workspace/team with access to the list/tasks. | Select list/rules, change one matching task and inspect delivery/run. |
| GitHub | Connect GitHub to install/authorize the Factorize App on the intended account/repositories; organization approval may be required. | Confirm active installation and repository selection, then send a matching event. |

The provider consent/installation screen is the authority for granted permissions. Grant access to the selected resources; changing those resources can require provider reauthorization. Job-trigger access and execution-agent access are separate: installing the Factorize GitHub App does not supply git credentials to an exe.dev VM.

MCP exposes safe connection/installation/target metadata, not tokens. Account connections, resource pickers and credential management require browser setup. Reconnect Linear/ClickUp from Settings; use GitHub's Configure installation link for repository access and verify the installation is active. Do not disconnect integrations while jobs still reference them; update those jobs first.

After changing access, create one controlled event and use `list_webhook_deliveries`, `get_webhook_delivery`, `list_job_webhook_activity`, and `list_runs` to verify delivery and execution. See [jobs not firing](/troubleshooting/events). Hosted Factorize manages OAuth application registration, callbacks and webhook infrastructure. Operators of their own deployment use [configuration](/self-hosting/configuration).
