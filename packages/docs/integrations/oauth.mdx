---
title: Integration access
description: Connect external services used by Trigger inputs and MCP clients.
---

Integrations hold server-side credentials used to validate provider webhooks or
make authorized API requests. Select only the integrations needed for your
Triggers or MCP connection. Credentials are encrypted and never returned by
Factorize APIs.

Bearer API, GitHub, Linear, ClickUp, X, Fly.io, exe.dev, Amp, and Cloudflare REST API
integrations have distinct setup flows. Cloudflare Tail is retired. Use the browser's Integrations page to connect or revoke
credentials and to choose which MCP clients may access them.

Choose **Delete** on a supported integration to preview its impact, then confirm.
Deleting removes the connection from Factorize, not the provider. For Linear,
Factorize removes its saved OAuth connection and webhook routing for that
workspace. Affected Trigger sources, Event lookups, and client or workload
access are listed before confirmation. A Trigger with no sources left is
removed, but Event definitions, subscriptions, and recorded occurrences are
kept. Reconnecting does not restore removed configuration or grants.


### Hetzner Cloud inventory and SSH checks

Add a Hetzner Cloud project with a read-only project token to view its server
inventory. Under **View servers**, enroll an existing server for SSH checks.
Use a dedicated non-root account, copy the server's Ed25519 host fingerprint
from a trusted console. Install the
complete restricted public-key line shown by Factorize in that account's
authorized keys. Factorize generates and stores the private key, and does not
return it to the browser or the client.

The owner can check **Hetzner Cloud (inventory and SSH checks)** in a client’s
permissions. The change takes effect on the current OAuth connection without
reconnecting it. An unchecked client cannot read Hetzner inventory or check SSH.
A checked client can call `list_hetzner_servers` or `check_hetzner_ssh` for any
owner-enrolled server. There is no separate per-server client selection.

Each SSH check revalidates the server’s project and enrolled public IPv4,
then authenticates using the pinned host key and stored credential. It closes
immediately, never opens a command channel, and returns no remote output.
The server needs a reachable public IPv4 address and SSH on port 22. If a
connection drops, repeat the check explicitly.

Deleting or replacing the project removes its saved SSH credentials in
Factorize. Also remove the public keys from the servers when retiring access.
Factorize does not change the provider or server as part of deletion.
