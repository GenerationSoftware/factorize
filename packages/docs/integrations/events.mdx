---
title: Event payloads and conditions
description: Define payload schemas and filter provider Trigger inputs.
---

An Event has a versioned JSON payload schema. Every Trigger attached to that
Event publishes an occurrence only when its resulting payload passes the current
schema. Stored occurrences keep their schema revision and payload.

Webhook Triggers can include conditions evaluated against prepared provider
context. The condition preview tool evaluates example data only; it does not
authenticate, route, or publish an occurrence. Repeated delivery IDs are
idempotent. Inspect safe outcomes with `list_trigger_webhook_activity` and
`list_webhook_deliveries`.

MCP subscribers receive resource update notifications after an occurrence is
stored. Notifications indicate that the resource changed; clients read the
resource or list occurrences to obtain durable data.

In the Factorize dashboard, open **Events** to see event definitions and their
subscriber counts. Select an event to see its payload schema, occurrence
history, and subscriptions. The **Subscriptions** sidebar shows registration
status and acknowledgment mode for your MCP connections in the current
workspace. The subscriber count includes active registrations only; an active
registration does not guarantee that the client can receive deliveries.
