# Credential proxy architecture being retired

The per-owner Fly credential proxy, browser pairing, and user-held unlock key
are the legacy architecture targeted by the breaking backend-proxy cutover.
Those paths are still present in the current repository checkpoint, so this
page no longer describes supported setup or recovery for the target design.
Do not interpret this migration checkpoint as proof that the runtime cutover
has shipped.

Use the [credential proxy cutover and recovery procedure](credential-cutover)
to drain existing runs, retire old proxy resources, reconnect credentials,
and repair affected jobs. Old user-encrypted secrets cannot be transferred;
owners must reconnect provider accounts or re-enter custom credentials.

The former design is retained in the repository's historical decisions and
Linear work for audit context. Fixture results from that implementation are
not live exe.dev or Fly identity evidence.
