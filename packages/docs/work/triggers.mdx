---
title: Create and edit Triggers
description: Attach input sources to Events and publish validated occurrences.
---

A Trigger belongs to exactly one Event. An Event can have multiple Triggers.
Triggers accept supported input sources such as schedules, signed webhooks,
provider events, and explicit fire requests. A match produces a durable
occurrence of the parent Event; it does not start an agent execution.

Use the browser or MCP `create_trigger` and `update_trigger` tools. Each Trigger
has a name, Event ID, source kind and source configuration. Updates replace the
configuration, so read the current Trigger first and include the intended full
configuration. Credentials are configured through integrations and are never
accepted in Trigger input.

## Sources and delivery

- **Schedule:** cron expression and timezone.
- **Webhook/provider:** provider-specific routing configuration, signatures,
  conditions and delivery identifiers.
- **Manual:** `fire_trigger` with a payload and idempotency key.

Duplicate provider deliveries and repeated manual keys do not create duplicate
occurrences. The Event's current JSON payload schema is validated before an
occurrence is stored. Occurrences retain the schema revision used at creation.
