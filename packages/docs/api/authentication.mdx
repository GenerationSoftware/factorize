---
title: Authentication and scopes
description: OAuth 2.1, device authorization, and access-token rules.
---

Protected REST and MCP requests use `Authorization: Bearer <token>`. Browser
users may also use their signed Factorize session cookie. Access is tenant-bound;
ownership and session version are rechecked on service calls.

## Scopes

| Scope | Allows |
| --- | --- |
| `team:read` | Read team settings |
| `team:write` | Update team settings |
| `triggers:read` | Discover Events, Triggers, and stored occurrences |
| `triggers:write` | Manage Events and Triggers |
| `integrations:read` | Read integration metadata and provider resources |
| `integrations:write` | Manage integration connections |
| `proxy:use` | Use authorized external integration APIs |
| `apps:manage` | Manage registered applications |

Scopes are independent; write does not imply read. Integration-specific scopes
are granted separately. Owner-only operations require an interactive browser
session.

Owners can edit the saved permissions for an existing MCP connection in
Settings. Removals restrict access immediately; adding scopes requires fresh
authorization and never increases a previously issued token's scope.
Workspace permissions marked Default are preselected for new browser
connections. They do not change existing grants. Reconnecting shows the
saved selection and distinguishes newly requested permissions; the client
must include all scopes it wants to retain or add when requesting step-up.

## OAuth clients

Authorization-code clients must use PKCE S256. Implicit and plain PKCE are
disabled. Access tokens last one hour; refresh tokens can last up to 30 days.
RFC 7009 revocation is advertised by discovery. Device authorization is also
supported for public clients; follow the advertised OAuth metadata and device
verification instructions.

Never send provider credentials to an API client. Stored integration secrets
are used server-side and omitted from responses.
