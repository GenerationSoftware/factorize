---
title: Events and Triggers
description: Understand Factorize's durable event model.
---

A **team** owns Events, Triggers, integrations, and authorization settings.

An **Event** is a named durable record with a versioned JSON payload schema. A
matching Trigger creates an occurrence, which subscribers can read later. An
Event may have multiple Triggers.

A **Trigger** watches one input source: a schedule, signed webhook, provider
notification, or explicit fire request. Matching and duplicate-delivery checks
happen before Factorize validates and stores the Event occurrence. A Trigger
publishes data; it does not launch an agent or create an execution.

MCP clients discover Event definitions, subscribe to their occurrence resource,
and receive a resource-updated notification after a new occurrence. They then
read the resource to obtain durable data. Occurrences are also available through
the authorized REST API, so a reconnecting client can recover stored data.
