---
title: Event and Trigger troubleshooting
description: Diagnose rejected inputs, missing occurrences, and subscription updates.
---

## No occurrence was created

1. Confirm that the Trigger is enabled and belongs to the intended Event.
2. Inspect its source configuration and integration connection in the browser.
3. For a webhook, inspect `list_trigger_webhook_activity` and
   `list_webhook_deliveries` for signature, condition, routing, or duplicate
   outcomes. These records omit secrets and raw payloads.
4. Check that the Event's current payload schema accepts the resulting JSON.
5. For manual firing, confirm the Trigger kind and reuse the original
   idempotency key when retrying an uncertain request.

## A subscriber missed a notification

Notifications tell the client that an Event resource changed; they are not the
stored payload. Read the Event resource or call `list_event_occurrences` to
recover durable occurrences after reconnecting. Confirm the client has
`triggers:read` and supports MCP resource subscriptions.
