---
title: Connection problems
description: Recover MCP authorization, scopes, and integration access.
---

| Symptom | Action |
| --- | --- |
| Browser consent fails or is cancelled | Sign in to the intended Factorize account, restart authorization from the client, and approve the requested scopes. |
| The authorization link expired or was used | Start **Reconnect** in the MCP client and open its new authorization link. Keep approval in the same browser and Factorize account. If only the consent form expired, reload it and review the choices again. |
| Saved permissions are missing from consent | Save the scopes in **Clients**, then start **Reconnect** from the MCP client. In Factorize, select the same existing connection. Available saved scopes are offered separately even when the client initially asks for fewer. The new token reports its scopes; an old access or refresh credential does not gain permissions. |
| Client never connects | Confirm `https://app.factorize.sh/mcp`, remote Streamable HTTP and OAuth support. Open the client's MCP status view and authenticate; see [connection guide](/mcp/overview). |
| `invalid_token` or access disappears | Reauthorize the client. A password reset or changing account security can invalidate delegated credentials. Browser sign-out alone does not revoke the client. |
| `insufficient_scope` | Reconnect and grant `triggers:read` to discover Events and occurrences, or `triggers:write` to manage Events and Triggers. Add integration scopes only when needed. |
| Provider input is not arriving | Check the saved integration and Trigger source configuration. For delivery diagnosis, see [Event troubleshooting](/troubleshooting/events). |

Revoking an MCP authorization affects access but does not delete stored Events,
Triggers, or occurrences. Provider reconnection is separate and can be managed
from the Integrations page.
