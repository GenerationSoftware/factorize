---
title: Connect your agent
description: Authorize a remote MCP client and control what it may do.
---

Use Factorize's remote Streamable HTTP endpoint in your MCP client:

```text
https://app.factorize.sh/mcp
```

Factorize uses OAuth. Sign in, review the scopes shown, and approve only the
permissions needed for the task. A team can mark permissions as defaults for
new consent. Defaults are suggestions, not changes to existing grants; explicit
a new connection stays within an explicit client scope request. To replace an
existing credential, start Reconnect in your client and select that same
connection in the Factorize consent page. You can approve its available saved
permissions even when the client requests fewer at sign-in. The response lists
the actual scopes issued. A client that separately narrows the token request
or rejects the returned scopes may still need changes. Existing tokens never
gain permissions.

In [Factorize](https://app.factorize.sh), review access in **Clients**
and approved services in **Integrations**. You can change or revoke client
access there. You do not need to paste a service credential into MCP.

## Built-in workflow skills

Use `skills/list` to discover `use-an-api`, `grant-vm-access`, and
`manage-triggers`. Use `skills/get` for the returned manifest, then read its
advertised resource URI. Rediscover the catalog after an update rather than
pinning an old versioned URI. Clients that do not expose these methods can
follow the [same recipes](/quickstart) in this guide.

See [MCP tools](/mcp/tools) for the registered inventory and
[REST reference](/api/reference) for the generated OpenAPI contract.
